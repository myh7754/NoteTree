# 디자인 정돈 + 라이트 모드 설계

작성일: 2026-10-04
상태: 검토 대기
시안: https://claude.ai/artifact/2nf3BGsHZfN7MdRznVHjD2 (A · 정돈, B · 종이, 소개 페이지)

## 배경

편집 화면과 소개 페이지에서 다섯 가지가 걸렸다.

1. 노드를 고르면 툴바 한 줄에 조작이 스무 개 넘게 놓인다. 전부 같은 회색 버튼이다.
2. 아이콘이 이모지·특수문자(🗺 🔍 ⌨ ⚙ 📝 ⟳)라 운영체제마다 모양이 다르다.
3. 기본 모양(상자)에서는 중심 주제와 맨 끝 노드가 똑같이 생겼다.
4. 색 팔레트가 툴바 가운데에 끼어든다. 고른 노드와 그 도구가 멀다.
5. 로고가 화면마다 다르고(🗺 / 🌳 NoteTree), 소개 페이지에 제품 화면이 없다.

## 정한 것 (2026-10-04 사용자 확인)

- 소개 페이지는 시안대로 간다.
- 시안 A의 배치를 적용하고, A의 색을 다크 모드로, B의 색을 라이트 모드로 둔다.
- **색 모드와 맵 모양은 서로 독립이다.** 색 모드는 다크/라이트, 맵 모양은 지금의
  상자/글자만/밑줄. 어느 조합이든 된다. (B 시안의 밑줄 노드는 "라이트 + 밑줄" 조합이다)
- **노드 도구는 고른 노드 위에 띄운다** (A 방식). B의 아래 띠는 만들지 않는다.

## 비목표

- 시안 C(툴바 없는 떠 있는 섬, 곡선) 전체
- 모바일·터치 대응
- 주인이 고른 색 모드·맵 모양을 방문자에게 그대로 보여 주기 (방문자는 자기 설정으로 본다)
- 노드 글꼴, 배경 무늬 선택

## 단계

셋으로 나누고, 단계마다 브라우저에서 확인받은 뒤 커밋하고 다음으로 간다.
각 단계는 혼자 배포할 수 있다.

### 1단계 — 소개 페이지

만지는 파일: `src/pages/Intro.tsx`, 새 `src/components/Logo.tsx`

- 첫 화면을 두 칸으로 나눈다. 왼쪽은 제목·설명·버튼, 오른쪽은 운영자 공개 맵 미리보기.
  좁은 화면에서는 위아래로 쌓인다.
- 미리보기는 그림 파일이 아니라 실제 맵이다. `loadPublicMapsByHandle(SHOWCASE_HANDLE)`의
  첫 맵을 `loadPublicMap`으로 불러 `MindMapCanvas`에 그린다. `PublicMapViewer`가 하는 것과
  같은 순서다(`readOnly` 켜기 → `openMap` → `expandToLevel(pickInitialDepth)`).
  소개 페이지는 비로그인일 때만 뜨므로 스토어를 편집 앱과 다투지 않는다.
- 미리보기는 조작할 수 없다(`pointer-events-none`). 칸 전체가 `/u/<닉네임>`으로 가는 링크다.
- 불러오지 못하면 미리보기 칸을 숨기고 지금처럼 글만 보인다. 대체 그림은 만들지 않는다.
- 사용법 네 단계는 가로 한 줄로 바꾸고, 번호 대신 그 단계에서 누르는 키를 앞에 둔다.
- 큰 버튼은 "예시 맵 열어 보기" 하나만 둔다. "사용법" 버튼은 네 단계가 첫 화면에 들어오므로
  뺀다. 로그인은 지금처럼 머리줄의 `AccountMenu`가 맡는다.
  (시안의 "로그인하고 시작" 버튼은 `AccountMenu`와 겹쳐서 만들지 않는다)
- "공개는 켜야 켜집니다" 단락과 처리방침 링크는 그대로 둔다.
- `Logo`는 선으로 그린 트리 표시 + "NoteTree" 글자다. 2단계에서 툴바와 공개 화면에도 쓴다.

### 2단계 — 편집 화면 배치 (시안 A)

만지는 파일: `Toolbar.tsx`, `FileMenu.tsx`, `ViewMenu.tsx`, `NodeStyleBar.tsx`,
`TextNode.tsx`, `TableNode.tsx`, `NoteDrawer.tsx`, `mapTheme.ts`, `PublicMapViewer.tsx`,
`PublicProfile.tsx`, 새 `src/components/Icon.tsx`

**툴바 — 세 구역**

| 구역 | 내용 |
|---|---|
| 왼쪽 | 로고, 맵 이름(`MapSwitcher`), 저장 상태 |
| 가운데 | 되돌리기, 다시 실행, 검색(넓은 칸 모양 버튼, `Ctrl F` 표시), 보기, 정렬 |
| 오른쪽 | 공개(`PublishMenu`), 계정(`AccountMenu`), ⋯ |

- ⋯ 는 `FileMenu`를 그대로 쓰고 "단축키", "설정" 두 항목을 더한다. 툴바의 ⌨ ⚙ 버튼은 없앤다.
  단축키(`?`, `Ctrl+,`)는 그대로다.
- 공개 여부는 툴바에 남는다 (맵마다 다른 설정은 툴바에 둔다는 기존 기준).
- `＋ 텍스트`, `＋ 표` 버튼과 색 팔레트는 툴바에서 빠져 노드 도구로 간다.
  툴바는 선택과 상관없이 모양이 같다.

**노드 도구**

- 노드 하나를 골랐을 때 그 노드 위에 뜬다: 자식 추가(Tab), 표 추가, 노트, 색 일곱 개와
  색 지우기, "가지" 토글, 삭제. (색과 "가지"는 지금의 `NodeStyleBar`를 그대로 옮긴다)
- `@xyflow/react`에 들어 있는 `NodeToolbar`로 만든다. 확대 배율과 상관없이 같은 크기로 보이고
  노드를 따라다닌다. 새 의존성은 없다.
- 편집 중(글자 입력), 읽기전용, 여러 개 선택일 때는 뜨지 않는다.
- 지금 마우스를 올리면 나오던 📝 ✕ 버튼은 없앤다. 내용이 있는 노트의 아이콘은 그대로 둔다.
- 노드가 하나뿐인 빈 맵에서는 캔버스 아래에 "노드를 고르고 Tab으로 가지를 칩니다"를 한 줄 보여 준다.
  추가 버튼이 툴바에서 사라진 것을 메운다.

**노드 모양 (상자)**

`mapTheme.ts`의 `classic` 분기만 바꾼다. `글자만`, `밑줄`은 그대로다.

- 중심 주제: 채운 상자, 큰 글자 (다른 두 모양과 같은 규칙)
- 1단계 가지: 가지 색을 옅게 깐 상자 + 가지 색 테두리
- 그 아래: 작고 옅은 상자 (2026-10-04 수정: 처음엔 글자만이었으나, 사용자가 "상자 모양은 모두 상자여야 한다"고 지적)
- 선은 가지 색을 쓴다 (지금은 깊이에 따라 남보라가 옅어진다)
- 사용자가 직접 칠한 색은 지금처럼 어느 깊이에서든 우선한다

**접기 버튼**

- 접힌 가지: `+14`처럼 숨은 후손 수를 적는다.
- 펼친 가지: `−`는 노드에 마우스를 올렸을 때만 보인다. 자리는 지금과 같아서
  (`absolute`) 노드 폭이 바뀌지 않는다.

**그 밖**

- `Icon.tsx`: 선 아이콘 열네 개쯤을 SVG로 직접 넣는다. 아이콘 라이브러리는 더하지 않는다.
- 노트 창 머리: 경로(`자바의신 › 객체지향`)를 작게, 그 아래 노드 이름을 크게. 📝 이모지는 뺀다.
- 공개 뷰어와 프로필의 머리줄도 같은 로고와 아이콘을 쓴다. 구성은 바꾸지 않는다.

### 3단계 — 라이트 모드 (시안 B의 색)

만지는 파일: `src/index.css`, `useMindMapStore.ts`, `main.tsx`, `SettingsDialog.tsx`,
`mapTheme.ts`, `BlockNoteEditor.tsx`, `exportImage.ts`, 색이 박힌 나머지 몇 곳

**설정**

- `colorMode: 'system' | 'dark' | 'light'`. 기본은 `system`. `localStorage`의 `color-mode`에 둔다
  (맵 모양·노트 패널 위치와 같은 "이 기기의 취향").
- 설정창 `화면` 탭 맨 위에 "색 모드: 시스템 따름 / 다크 / 라이트".
- 실제 적용은 `<html data-theme="dark|light">`. `system`이면 `prefers-color-scheme`을 보고,
  운영체제 설정이 바뀌면 따라간다. 첫 그림 전에(`main.tsx`에서 렌더 전) 붙여 깜빡임을 막는다.
- 공개 뷰어·프로필·소개·처리방침도 같은 값을 따른다. 방문자는 저장한 게 없으니 시스템 설정으로 본다.

**색을 바꾸는 방법**

Tailwind v4는 `bg-slate-900` 같은 클래스를 `var(--color-slate-900)`으로 낸다. 그래서
컴포넌트의 클래스 260여 곳을 고치지 않고, `index.css`에서 라이트일 때 변수 값만 바꾼다.

```css
:root[data-theme='light'] {
  --color-slate-950: #f6f8f2; /* 캔버스 */
  --color-slate-900: #ffffff; /* 툴바, 노트 창, 메뉴 */
  /* … 800~50까지 밝기를 뒤집어 대응 */
}
```

- `ponytail:` 이름(`slate-900`)과 실제 색(흰색)이 어긋난다. 주석으로 남기고, 색 이름이 헷갈려
  실수가 나오기 시작하면 그때 `bg-surface` 같은 의미 이름으로 옮긴다.
- 3단계의 첫 작업은 이 방법이 실제 빌드에서 먹는지 한 화면으로 확인하는 것이다.
  안 먹으면 의미 이름 토큰으로 옮기는 원래 방식으로 간다 (품이 커진다).
- 어두운 바탕을 전제로 한 `text-white`는 따로 찾아 고친다 (노드 입력칸, 설정창 선택 표시 등).
  남보라 버튼 위의 흰 글씨는 그대로 둔다.

**클래스가 아닌 색**

- `index.css`의 노트 모양(제목, "핵심" 상자, 형광펜, 코드): 색을 변수로 빼고 라이트 값을 준다.
  "핵심"은 옅은 노랑 상자, 형광펜은 노랑.
- `BlockNoteEditor`의 편집기 테마를 색 모드에 맞춘다.
- `mapTheme.ts`: 노드·선 색을 CSS 변수로 쓴다(`var(--node-bg)`, `var(--branch-0)` …).
  가지 색 여섯 개는 밝은 바탕에서 읽히도록 한 단계 진한 값을 라이트용으로 둔다.
- 사용자가 칠하는 색 일곱 개는 그대로 둔다. 진한 색 위에 흰 글씨라 밝은 바탕에서도 읽힌다.
  `글자만` 모양에서 옅게 깔리는 경우만 브라우저에서 확인하고, 안 읽히면 그때 조정한다.
- PNG 내보내기 바탕색은 지금 화면의 캔버스 색을 읽어 쓴다.
- 설정창의 작은 미리보기 그림(`ThemePreview`, `DirectionPreview`)도 변수를 쓴다.

## 검증

단계마다:

- `npx tsc -b`, `npx vitest run --no-file-parallelism`, `npm run lint`
- 바뀌는 로직의 테스트
  - 1단계: 미리보기 불러오기 실패 시 글만 남는 것
  - 2단계: `mapTheme` 상자 모양의 깊이별 결과, 접힌 가지의 후손 수, `Toolbar`·`FileMenu` 기존 테스트 갱신
  - 3단계: `colorMode` → `data-theme` 결정 (system일 때 운영체제 설정을 따르는 것 포함)
- 브라우저 확인은 사용자가 한다. 3단계는 다크/라이트 × 상자/글자만/밑줄 여섯 조합과
  노트 창, 설정창, 공개 뷰어, 소개 페이지, PNG 내보내기를 본다.

## 걸리는 점

- 노드 도구가 윗줄 노드를 가린다. 고른 동안만이고, 화면 위쪽 끝에서는 `NodeToolbar`를 아래로 돌린다.
- 상자 모양을 바꾸면 공개 맵 방문자가 보는 기본 모양도 같이 바뀐다 (방문자는 기본 모양으로 본다).
  의도한 결과지만 이미 뿌린 링크의 첫인상이 달라진다.
- 소개 페이지 미리보기는 첫 화면에 서버 요청 두 번을 더한다 (목록, 맵).
